# 持续滚动优化实验（2026-09-22）

## 结论与交付范围

本轮完成了成本分项测量和候选实现验证，**没有新增生产代码优化**。候选没有
同时满足“显示效果完全不变”和“持续滚动性能可验证改善”，全部留在临时副本，
未合入工作区。前一轮的导航候选列表缓存改动及测试保持原样。

玻璃边框整体是当前课程页的重要瓶颈；不能仅归因于导航滤镜或 20px 内发光。
饱和细边、白色高光、内发光及多层遮罩的组合均需关注。导航节点合并、边框
containment 没有带来一致收益；独立图层缓存和透明区域裁剪出现了像素差异。

本轮没有降低模糊、圆角、饱和度、高光或边框强度，也没有改变 Accordion 的
局部图层提升修复。不能宣称滚动帧率或此前 4.8～6.3 倍的主线程成本已改善。

## 方法

- 当前源码加前一轮导航查询优化的隔离 Next.js 生产构建，webpack 编译和
  TypeScript 检查通过。测试开关只加入隔离副本。
- Windows / Chrome 153 / Intel Iris Xe，桌面 1440×900、DPR 1、暗色图片背景。
  像素验证另覆盖 1231×851 / DPR 1.25、390×844 / DPR 2、浅色渐变背景。
- 18 个课程、12 张单词卡，API 固定测试数据，不使用真实业务数据。
- 同一个已加载页面切换实验，共享壁纸纹理；每种模式先预热再测量。正反顺序
  交替，固定速度的真实 CDP 鼠标滚动，每样本两段约 2 秒，计时约 4.4～4.6 秒。
- 课程页从 scrollY=450 开始往返 1400px；单词页从顶部往返 359px。
- 使用 `FrameSequenceTrackerV3` 的 WheelScroll `dropped_v4 / expected`
  记录浏览器滚动丢帧；另记录 rAF 间隔和 renderer TaskDuration。
  每个常规样本两个 tracker，记录到 231～239 个预期帧。
- 54 个完成的常规样本：首轮消融 24 个、导航矩阵候选 6 个、containment
  候选 18 个、细边/高光消融 6 个。额外详细 trace 只用于诊断，不并入这些平均值。
- 所有表格是各自同期样本平均。基线会随浏览器/GPU 状态变化，不能跨系列
  比绝对数字；手机尺寸截图也不代表真机功耗或温度测量。

“隐藏/禁用”仅为定位成本的消融实验，会改变画面，**不是交付的优化方案**。
noNav 仅禁用 CSS filter，保留导航控制器、布局和 SVG 坐标更新，避免混入
控制器减少的收益。

## 成本分项结果

每种模式每页两次。主线程时间是整个采样窗口的累计任务时间，不是每帧时间。

| 课程页模式 | rAF 平均间隔 | 滚动丢帧比例 | 主线程任务 |
| --- | ---: | ---: | ---: |
| 完整效果 | 29.37ms | 49.37% | 657ms |
| 禁用导航滤镜 | 28.03ms | 46.22% | 659ms |
| 隐藏完整玻璃边框，保留内阴影 | 16.67ms | 0% | 584ms |
| 只隐藏附加内阴影 | 26.79ms | 43.04% | 816ms |
| 同时禁用导航和隐藏边框 | 16.67ms | 0% | 495ms |
| 只隐藏内发光 | 26.08ms | 42.07% | 729ms |

单词页同期完整效果平均 17.26ms、4.6% 丢帧；隐藏边框后 16.67ms、0% 丢帧，
主线程任务约 1119→626ms。其完整效果基线明显不同于旧报告中的 24.87ms，
因此不能拿本轮绝对数值当作已实现的优化收益。

细边和高光另开系列，每种两次：

| 课程页模式 | rAF 平均间隔 | 滚动丢帧比例 | 主线程任务 |
| --- | ---: | ---: | ---: |
| 完整效果 | 28.86ms | 48.00% | 851ms |
| 只隐藏饱和细边 `::after` | 22.35ms | 31.34% | 895ms |
| 只隐藏白色高光 `::before` | 22.47ms | 31.00% | 879ms |

这表明去掉单项能改善丢帧，但没有消除瓶颈，而且更流畅并不保证采样窗口内
主线程总时间更少：更多帧可能意味着执行更多绘制/更新。不能把各项收益相加，
也不能把 rAF 倒数当作直接测得的呈现 FPS。

## 候选实现结果

### 导航颜色矩阵兼任输出裁剪

将末端零位移 feOffset 的输出子区域移到逐像素的 feColorMatrix，减少一个
SVG 节点；保留输入模糊范围、完整宿主输出、清晰正文及合成顺序。
7 项临时几何/节点回归测试通过。课程页三对同期数据：

| 指标 | 原实现 | 候选 |
| --- | ---: | ---: |
| rAF 平均间隔 | 25.18ms | 25.20ms |
| 主线程任务 | 856.36ms | 854.20ms |
| 滚动丢帧比例 | 38.09% | 38.99% |

主线程仅相差约 −0.25%，帧间隔及丢帧没有改善，不能认定有效优化，未合入。
部分切换截图还有与重复滚动有关的像素波动，未继续为无性能收益的方案扩大验证。

### 边框布局隔离

原 `.glass-border` 已有 `contain: paint`。分别实验 `layout paint` 和 `strict`。
两个候选各通过 12 组静态逐像素比较，但同期滚动数据没有一致收益：

| 页面 / 模式 | rAF 平均间隔 | 主线程任务 | 滚动丢帧比例 |
| --- | ---: | ---: | ---: |
| 课程页 / 原实现 | 28.31ms | 845.51ms | 46.35% |
| 课程页 / layout paint | 27.49ms | 832.00ms | 46.10% |
| 课程页 / strict | 27.59ms | 863.02ms | 46.31% |
| 单词页 / 原实现 | 20.13ms | 1235.67ms | 20.34% |
| 单词页 / layout paint | 20.18ms | 1249.17ms | 21.18% |
| 单词页 / strict | 20.77ms | 1210.53ms | 23.44% |

每种每页三次。课程页的小幅变化未在单词页复现，strict 还增加了丢帧，均未合入。

### 未通过画面验证的候选

- 内阴影、白色高光、内发光层、内发光背景或饱和细边独立使用 opacity 图层缓存。
- 毛玻璃背景层增加 paint/strict containment；内发光层增加 paint containment。
- 不改变渐变尺寸，只用 evenodd polygon 裁掉边框中央完全透明的区域。

最后一个方案在课程页 DPR 1.25 的一次对照中，4,087 个 RGB 通道发生变化，
最大差值 10/255；切回原实现的对照为 0。可见即便删的是理论透明区域，
额外 clip 也会影响浏览器的实际合成或栅格结果。所有这些方案均未采用。

没有尝试把完整导航 filter 输出缩到当前视口：异步滚动可能先展示旧栅格，
再执行主线程更新，导致新进入视口的清晰正文被旧裁剪区域截掉。有限预留范围
不能保证任意快速滚动都不露出被裁区域，不符合本轮视觉约束。

脚本位于同一 Temp 根目录：`glass-scroll-common.mjs`、
`glass-scroll-benchmark.mjs`、`glass-scroll-visual.mjs`、
`glass-scroll-direct-visual.mjs`。测试配置由 GLASS_VARIANTS / GLASS_ROUNDS /
GLASS_TAG 等环境变量选择，详细 trace 使用 GLASS_TRACE=full。

常规测量只打开轻量 benchmark trace；其中 main 为空表示未采集 Paint 等事件，
不能解释为没有绘制。详细 trace 额外采集绘制、栅格和图层事件，记录的事件
持续时间可能嵌套或跨线程，不能直接相加成整机 CPU 开销。样本不包含真机
持续发热/功耗，也不足以为所有硬件给出统一提升百分比。

详细诊断的四个样本没有页面异常；隐藏边框后，两个页面记录到的 Paint、
Layerize 和 RasterTask 持续时间均下降。它们支持边框绘制/合成确有成本的
判断，但单次带完整 trace 的结果不用于计算最终优化百分比。

收尾确认：生产玻璃 CSS、配置、组件和控制器与本轮开始时一致，前一轮的
六项导航回归测试仍全部通过，`git diff --check` 通过。端口 8098 的临时服务
已经关闭，用户原有开发服务未停止。

本轮结果限定为：**已测的安全候选未达到验收，不等于证明所有实现都无法优化。**
若要继续争取大幅提升，剩余方向需要对固定背景与多层边框遮罩的渲染结构做
更深入的原型验证，不能再预先保证现有每个像素和滚动行为完全一致。
