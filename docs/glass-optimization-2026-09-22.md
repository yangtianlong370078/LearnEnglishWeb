# 保持玻璃显示效果的优化验证（2026-09-22）

后续针对持续滚动完成了独立实验，见
[持续滚动优化实验](glass-scroll-investigation-2026-09-22.md)；后续没有新增
通过“零视觉变化且性能实测改善”验收的生产改动。

本次约束是圆角、玻璃边框、毛玻璃、高光、饱和度和背景透色均不得改变。
最终保留导航控制器的查询缓存优化；尝试的 CSS 绘制简化未满足逐像素一致，
已经全部撤回。当前没有证据支持“效果完全不变且滚动性能显著提升”的承诺。

## 保留的改动

`lib/glass-navigation-source.ts` 过去将 main 内每次子节点变化都视为玻璃容器
集合变化。按钮内容、文本、图标等普通更新也会重新查询所有候选容器并遍历祖先。

现在仅在新增/删除的子树包含玻璃容器、导航内容标记变化或收到玻璃注册/卸载
通知时使候选列表失效。所有原有 DOM 变化仍安排下一帧读取实时位置，因此
普通内容导致的布局移动、容器重挂载和嵌套变化仍会更新导航滤镜。

这项优化减少业务更新期间的 DOM 查询和祖先遍历。稳定滚动原来就复用了该
列表，因此不应把查询减少比例解释成整页性能或滚动帧率的提升比例。边框遮罩、
固定背景和合成的主要成本仍然存在，没有实测手机温度或耗电改善。

玻璃 CSS、数值配置、纹理生成、滤镜、装饰 DOM 及图层提升规则均保持原样。
`/learnwords` 两个 Accordion 容器的局部禁用图层提升修复也保持原样。

## 未采用的绘制方案

- 将四边相同强度合为单个 mask/opacity：小圆角时原遮罩分块会重叠；
  同时存在 alpha 量化和亚像素边缘差异。
- 缩小线性深度渐变的图像尺寸，裁去透明尾部：数学上透明区无贡献，但实际
  浏览器在非整数尺寸、DPR 2/3 下改变了渐变栅格化结果。
- 仅将等强度圆角的 conic-gradient 换成同尺寸的常量 linear-gradient：
  缓存状态的合成页面测试通过，但真实课程页在 1231×851、DPR 1.25、暗色
  图片背景和导航滤镜叠加时出现差异。一次比较有 34,347 个 RGB 通道不同，
  最大差值 6/255；切回原实现的 A/A 比较为 0，不能按零差异接受。
- 对内发光层额外提升图层：探索性滚动样本出现帧间隔和主线程时间的取舍，
  没有采用，也没有改变现有的合成策略。

这些临时实验只用于筛选，不是最终代码的性能结果。尤其不能把实验版本的
滚动数据当作本次提交后的收益。

## 浏览器检查方式

Chrome 153、GPU 加速、API 固定测试数据。隔离生产副本仅为测试加入原始/
优化回调切换，在同一个已加载页面内比较，以共享完全相同的壁纸纹理，避免
重新加载时随机抖动纹理影响截图。测试包含浅/深色、图片/渐变背景，以及
DPR 1、1.25、2、3。手机尺寸来自桌面浏览器模拟，不代表手机真机性能。

每轮进行 20 次普通 DOM 更新，同时改变并恢复已有容器的位置。检查主容器
查询次数、最终 SVG 滤镜几何和截图；另做原始实现重复运行的 A/A 对照。

16 组（两个页面各八组）的查询次数与滤镜几何检查均通过：预热后每轮查询
从 20 次降为 0 次，滤镜几何一致，没有页面运行异常。

首次完整截图矩阵中，15 组 A/B 为零差异；单词页 DPR 1.25 的一组有 37 个
RGB 通道差 1/255，其 A/A 对照也出现相同规模变化。随后对两组 DPR 1.25
场景做只运行旧回调的独立重复实验，仍复现像素波动（浅色组有 52,740 个通道
变化，最大 3/255）。因此不能声称所有截图逐像素稳定，也不能把这个旧实现
同样存在的现象归于查询优化。最终保留项没有修改任何绘制代码或参数，
新旧滤镜输入几何一致。截图验证的这一限制原样记录，不以容差掩盖。

另做八组 Accordion 回归（桌面/手机尺寸 × 浅/深色 × 图片/渐变背景），每组
展开收拢三次。24 次精选课程截图比较全部为 0 差异；局部禁用图层提升的范围
仍只有两个课程容器，普通玻璃组件继续使用原提升策略。
