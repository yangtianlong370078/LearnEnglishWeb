# 液态玻璃实现与性能验证

主题菜单现在提供「卡片 / 玻璃 / 液态玻璃」。旧 `glass-enhance=off/on`
设置自动迁移为卡片/玻璃；首次升级不会自动启用液态玻璃。
「液态玻璃」仅在「图片」主题下可选；「默认」主题中该选项禁用。
从图片液态切到默认时立即退回玻璃并释放资源；切回图片不会自动重启液态。
旧的「默认 + 液态」保存组合在刷新时也会归一为玻璃，不加载液态渲染器。

## 实现与现有效果

- 卡片和玻璃继续使用原来的 CSS、毛玻璃缓存、边框、内发光与内容层。
  液态模式保留玻璃模式的全部层，仅在 `.glass-warp` 内添加边缘折射画布。
- 直接复用现有全屏毛玻璃缓存纹理，避免 DOM 截图、重复模糊和额外的 FBO
  全屏复制。静态背景只上传一次，主题/窗口尺寸变化后才更新。
- 一个独立 WebGL2 context，共享 shader，通过 `drawArraysInstanced`
  批量绘制全部活跃卡片。这相当于 InstancedMesh 的底层实例化绘制，不引入
  Three.js。每帧 WebGL 部分一次 draw，另外每卡一次 2D `drawImage`，
  最后由浏览器合成；**不是整个页面只有一次绘制**。
- 各卡片占用独立 atlas 区域，避免重叠卡片互相污染。裁片回到原卡片背景层，
  所以文字、菜单、圆角裁剪、tint 和边框仍按原 DOM 层级显示。
- 圆角 SDF + `smoothstep` 产生透镜 mask，使用屏幕坐标偏移采样，叠加
  菲涅尔反光和可选 RGB 分离。中心透明；最外侧不添加折射的宽度由
  `edgeInsetPx` 控制，默认 2 CSS px，向内保留 1 CSS px 的平滑过渡。
  采样的是站点壁纸，不包括透镜后方其他卡片/文字。
- 导航依赖现有页面内容滤镜、登录页使用独立背景，继续使用原玻璃。
  弹窗打开和卡片布局动画期间暂停液态层，保留原效果，避免错误背景或滞后纹理。

## 参数

全部参数位于 `config/liquid-glass.ts`，修改后刷新，生产环境重新构建。

| 参数 | 默认值 / 含义 |
| --- | --- |
| `edgeWidthPx` | 28，透镜宽度 |
| `edgeInsetPx` | 2，最外侧不折射区域的宽度（CSS px）；支持非负小数，0 取消固定保留带，仍保留 1 CSS px 平滑过渡 |
| `refractionPx` | 14，最大折射偏移 |
| `fresnelStrength` | 0.12，附加菲涅尔高光 |
| `dispersionPx` | 1.25，RGB 分离距离 |
| `disableDispersionDesktop` | false，PC 开启色散 |
| `disableDispersionMobile` | true，移动端关闭色散 |
| `desktop` | 最多 12 张、DPR 上限 1、atlas / 纹理各 150 万像素 |
| `mobile` | 最多 8 张、DPR 上限 1、atlas / 纹理各 50 万像素 |
| `mobileBreakpointPx` | 768；粗指针设备也使用移动预算 |
| `adaptive` | 连续 8 次慢更新后，本次滚动降级；结束 160ms 后恢复 |

色散开关是 shader 编译期变体：关闭后每片元 1 次纹理采样，开启为 3 次。
原有模糊、边框和内发光仍在 `config/glass.ts` 调整，两套配置相互独立。

## 性能保护

- 只有选择液态模式才动态加载 controller/shader；其他模式不创建 WebGL。
- IntersectionObserver 筛选视口候选，超额和超大背景保留玻璃。滚动事件只
  安排共享 rAF，批量读位置后才写画布；坐标变化复用 atlas 排布。
- 画面没变化不绘制，页面隐藏/弹窗打开时停止；没有持续运行的动画循环。
- 连续慢帧保护同时检查更新耗时（8ms）及相邻更新间隔（34ms），会主动退回
  玻璃。该间隔包括整页原有绘制成本，不代表液态 renderer 自身耗时。
- WebGL2 不可用、主要性能风险驱动、创建/上传/绘制失败或 context loss 时，
  自动切换到玻璃，并同步菜单与持久化设置。
- 退出时取消 rAF/定时器，断开 observer/listener，移除装饰 Canvas 和动态
  CSS，释放 texture/buffer/program/context；未完成的模块/图片加载不会重启它。
- 过滤装饰 Canvas 增删，避免触发原 Providers 的全卡片尺寸校正。

按每像素 RGBA8 估算，背景纹理 + atlas + 所有卡片 Canvas 的基础像素存储
上限约为桌面 **18MB**、移动端 **6MB**。这不包含浏览器双缓冲、GPU 驱动副本、
原有玻璃缓存及临时上传画布，不能当作实际显存占用测量。

## 验证方法与限制

`tests/liquid-glass.browser.mjs` 在隔离生产服务上运行真实 `/courselearn`
和 `/learnwords`，API 全部使用虚构数据，不访问真实后台。测试覆盖持久化、
无 WebGL/context loss 回退、静止零绘制、活跃上限、退出资源释放及模式往返。

使用 Chrome 硬件加速、CDP 原生滚轮手势；各模式预热后上下滚动各约 2 秒，
正反顺序交替。记录 rAF 平均/p95、超过 25ms 的帧比例、主线程 TaskDuration、
WebGL draw/上传次数与降级占比。rAF 不是 GPU 实际呈现 FPS；TaskDuration
不是整机 CPU/GPU 功耗。移动配置是桌面模拟，不能据此断言手机温升或续航。

24.85–30.28ms、手机尺寸 18.17–19.68ms，说明短测量的波动不可忽略。

## 首批 8px 配置测量

Chrome 153.0.8010.48 / Intel Iris Xe / ANGLE D3D11，确认 GPU 合成、Canvas2D
和 WebGL 硬件加速。桌面 1440×900 / DPR 1；手机尺寸 390×844 / DPR 2，
仍使用同一台桌面机器。以下是每场景每模式两次样本指标的平均值。

这批性能采样使用开始实现时的 `glassConfig.blurPx = 8`。收尾时工作区的原有

8px 配置的对照数据，不宣称是新 2px 配置的精确耗时或卡顿比例。

| 场景 | 玻璃平均帧间隔 | 液态平均帧间隔 | 玻璃 → 液态 p95 | 玻璃 → 液态主线程任务 |

任务时间是约 4.2–4.4 秒采样窗口内的累计主线程任务，**不是每帧耗时**。
桌面单词页超过 25ms 的帧从 44.9% 增至 53.7%；手机尺寸单词页从 2.2% 增至
13.5%，尾部帧间隔明显增加。因此当前实现仍有滑动卡顿风险，不能说成本为零。

## 旧模式与资源回归验证

以首批 8px 配置独立构建旧版和新版，在两个真实路由、桌面/手机尺寸、暗色图片/浅色渐变、
卡片/玻璃模式共 16 组场景中比较约 1,503 万个卡片像素。为保证输入一致，
固定原有壁纸随机抖动，并统一原有 `--glass-repaint-nudge` 重绘偏移相位。
14 组首对截图 RGB 完全一致；另两组的 1–2/255 差异也出现在旧版自身重复
截图中，新版与重复旧版截图的卡片区域逐像素一致。所有场景的几何、计算样式、
玻璃 CSS 规则和变量相同，两版 WebGL 申请数均为 0。

最终四组合浏览器功能验证全部通过：

- 正常「玻璃 → 液态 → 玻璃」的卡片区域 RGB 差异为 0。
- 设置刷新后保持；退出后画布、活跃 context、后续 draw 全部归零。
- 无 WebGL 和强制 context loss 均自动回到玻璃。
- 人工放慢 draw 后，第 9 次滚动更新检测到降级并清空液态层；停止滚动后恢复。
- 弹窗状态暂停并清空液态层，关闭后恢复；静止没有绘制。
- 没有页面异常、真实 API 访问或后台写入。

强制 context loss 会引起浏览器已有渐变层重新栅格化，因此它单独验证回退，
不混入普通模式往返的视觉对照。桌面课程页导航图标的少量像素差在纯玻璃菜单
开关控制组中也出现，卡片区域始终相同。

最终功能报告位于上述目录的 `results-functional-final/results.json`，
旧模式对照结论为 `legacy-visual-conclusion.json`。早期性能报告中的截图差异
保留作调查记录，最终视觉结论以上述独立功能及旧模式对照为准。

## 使用建议

液态玻璃增加 GPU 片元采样、跨 Canvas 复制和合成工作，持续滑动仍可能掉帧、
增加功耗及发热，尤其是高刷新率或较弱移动 GPU。静止时零更新可避免持续渲染
造成的额外负担，但不能保证所有设备完全不发热。优先保留移动端关闭色散，
必要时降低 `maxPixels` / `maxCards`，保留自适应保护；需要最稳定性能时选玻璃。
